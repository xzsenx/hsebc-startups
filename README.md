# Стартапы и вакансии — модуль поиска команды

Прототип модуля для мини-приложения Бизнес-клуба: участники размещают стартапы и вакансии,
находят друг друга в ленте и откликаются, авторы принимают решения по откликам.

**Основной сценарий:** Анна публикует вакансию → Максим находит её в ленте и откликается →
Анна видит отклик во «Входящих» и принимает его → контакты в Telegram открываются обеим
сторонам, Максим видит решение у себя в кабинете.

## Живой стенд

**http://23.26.37.241:8090** — развёрнуто на моём сервере, можно потыкать без установки.
Вход в один клик демо-аккаунтом, Swagger — на `/api/docs`.

Стенд намеренно запущен с `ENVIRONMENT=development`: иначе приложение не стартует
с демо-аккаунтами, а без них смотреть нечего (проверка описана в разделе «Безопасность»
и покрыта тестами). `JWT_SECRET` на стенде свой, случайный. HTTPS нет — сервер
занят другими проектами, а ради демо трогать общий прокси не хотелось.

## Продукт: жизненный цикл

**Публикация:** `open` → `closed` → снова `open`. Закрытая пропадает из ленты, но открывается
по прямой ссылке с пометкой «Набор закрыт» — тот, кому её переслали, увидит понятный статус, а не 404.

**Отклик:**

```
            ┌──────────► accepted   (контакты открыты обеим сторонам)
pending ────┼──────────► declined
            └──────────► withdrawn  (кандидат отозвал) ──► pending (откликнулся снова)
```

- Решение принимает только автор и только по откликам в `pending`. Принятое решение финально:
  кандидат не должен видеть, как его то принимают, то отклоняют.
- Кандидат может отозвать отклик, пока решения нет. Автор отозванные отклики не видит.
- Повторный отклик после отзыва переиспользует ту же запись, а не создаёт новую.

## Модель данных

```
users ──< posts ──< applications >── users
```

- **users** — имя, чем занимается, о себе, ник в Telegram, хеш пароля.
- **posts** — публикация. Поле `kind` различает стартап и вакансию: поведение у них одинаковое
  (лента, отклики, закрытие), поэтому две таблицы дублировали бы схему и роуты.
- **applications** — отклик: статус, сообщение, `decided_at`.

`UNIQUE (post_id, applicant_id)` — один участник откликается на публикацию один раз. Это
ограничение **в базе**: двойной клик и параллельные запросы не создадут дубль, даже если
проверка в коде пропустит гонку.

Миграции — Alembic: `0001` создаёт схему, `0002` добавляет статус `withdrawn`.

## API

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/auth/register` | Регистрация, возвращает токен |
| POST | `/api/auth/login` | Вход |
| GET / PATCH | `/api/auth/me` | Свой профиль: получить / изменить |
| GET | `/api/posts` | Лента: `kind`, поиск `q`, `limit`/`offset` |
| POST | `/api/posts` | Создать публикацию |
| GET | `/api/posts/mine` | Свои публикации со счётчиком новых откликов |
| GET | `/api/posts/{id}` | Публикация целиком |
| PATCH | `/api/posts/{id}` | Изменить, закрыть или открыть (только автор) |
| POST | `/api/posts/{id}/applications` | Откликнуться |
| GET | `/api/posts/{id}/applications` | Отклики на публикацию (только автор) |
| GET | `/api/me/applications` | Отправленные отклики и решения по ним |
| GET | `/api/me/applications/received` | Полученные отклики |
| GET | `/api/me/summary` | Счётчики для бейджа в навигации |
| PATCH | `/api/applications/{id}` | Принять или отклонить (только автор публикации) |
| POST | `/api/applications/{id}/withdraw` | Отозвать свой отклик |

## Принятые решения

**Вход по почте и паролю, а не через Telegram.** В мини-приложении пользователь приходит
авторизованным через `initData`, но для проверяемого прототипа это неудобно: нужны бот и
туннель. Авторизация собрана в двух файлах (`security.py`, `deps.py`) — заменить её на проверку
`initData` можно, не трогая остальное. Интерфейс уже готов к Telegram: подхватывает тему,
вызывает `ready()`/`expand()`, использует системную кнопку «Назад» и тактильный отклик.
Вне Telegram всё это отключается само.

**Контакты — только после принятия отклика.** В ленте и карточке видно имя и род занятий, но
не Telegram. Иначе лента превращается в справочник контактов, а отклик теряет смысл.
Скрытие сделано на сервере — через API контакт тоже не достать.

**Лента открыта без входа, действия — нет.** Человек видит, что в Клубе ищут, ещё до регистрации.

**Состояние ленты — в URL.** Фильтр и поиск лежат в адресе: ссылкой можно поделиться, «Назад»
возвращает ровно туда, где человек был.

### Повторные действия и ошибки

| Ситуация | Поведение |
|---|---|
| Повторный отклик | 409, интерфейс обновляет карточку и спокойно объясняет, без красной ошибки |
| Двойной клик по «Отправить» | Кнопка блокируется на время запроса; в базе дубль не создаётся |
| Одновременно «принять» и «отклонить» с двух вкладок | Применяется ровно одно (атомарный условный UPDATE) |
| Повторное нажатие того же решения | 200, тот же результат |
| Попытка изменить принятое решение | 409 |
| Отклик на свою / закрытую публикацию | 403 / 409, кнопки в интерфейсе нет |
| Решение по отозванному отклику | 409 «Кандидат отозвал отклик» |
| Чужая публикация или отклик | 403; чужой отклик при отзыве — 404, чтобы не раскрывать, что id существует |
| Сессия истекла | Любой 401 разлогинивает и ведёт на вход с возвратом на ту же страницу |
| Нет сети / сервер упал | Понятное сообщение и кнопка «Повторить» |
| Пустая лента, пустой поиск, пустой кабинет | Отдельные состояния с подсказкой и действием |
| Закрытие вкладки с несохранённой публикацией | Браузер переспрашивает |

## Безопасность

Я провёл аудит своего же кода и зависимостей. Каждая находка ниже закрыта, и на каждую есть
тест в `backend/tests/test_security.py`, чтобы исправление нельзя было незаметно откатить.

### Найдено и исправлено

| # | Проблема | Чем грозило | Исправление |
|---|---|---|---|
| 1 | `python-jose` 3.3.0 — путаница алгоритмов (CVE-2024-33663 и её неполное исправление) | Подделка JWT | Заменён на PyJWT, алгоритм зафиксирован в коде, а не берётся из окружения |
| 2 | Устаревшие `starlette` и `python-multipart`, транзитивный `ecdsa` | Известные DoS и прочие CVE | Обновлены, ненужные пакеты удалены; `pip-audit` и `npm audit` — 0 уязвимостей |
| 3 | `passlib` заброшен, тянет удалённый в Python 3.13 модуль `crypt` | Поломка при обновлении Python | Прямое использование `bcrypt` |
| 4 | bcrypt молча обрезает пароль до 72 байт; кириллица — 2 байта на символ | Разные длинные пароли с общим началом совпадали бы | Лимит 72 **байта**, а не символов |
| 5 | Нет ограничения попыток входа | Перебор паролей | Скользящее окно в бэкенде + `limit_req` в nginx |
| 6 | Время ответа входа зависело от того, есть ли почта в базе | Перебор зарегистрированных почт по таймингу | bcrypt выполняется и для несуществующей почты |
| 7 | Лимит попыток можно было обойти подменой `X-Forwarded-For` | Бесконечный перебор | nginx перезаписывает заголовок, бэкенд наружу не опубликован |
| 8 | Гонка при одновременных решениях по отклику | Кандидата «приняли» и «отклонили» одновременно | Атомарный `UPDATE … WHERE status = 'pending'` |
| 9 | Контакт автора отдавался в API до принятия отклика | Утечка персональных данных | Скрытие на сервере, а не в интерфейсе |
| 10 | Символы `%` и `_` в поиске работали как шаблоны LIKE | Поиск «%» отдавал всю ленту | Экранирование |
| 11 | Лишние поля в запросе молча игнорировались | Риск массового присваивания при доработках | `extra="forbid"`: лишнее поле — ошибка 422 |
| 12 | `JWT_SECRET` по умолчанию годился бы и для продакшена | Подпись токенов известным всем ключом | В production приложение не стартует со слабым секретом или демо-аккаунтами |
| 13 | Редирект после входа по `?next=` | Открытый редирект на чужой сайт (`?next=//evil.com`) | Разрешены только внутренние пути |

### Защита в глубину

- **Заголовки:** строгая CSP (скрипты — только свои и SDK Telegram, без инлайна и `eval`;
  встраивание — только в веб-версию Telegram), `nosniff`, `Referrer-Policy`, `Permissions-Policy`.
  Ответы API не кешируются (`no-store`), версии серверов скрыты.
- **Контейнеры:** бэкенд работает не от root и на файловой системе только для чтения; nginx —
  непривилегированный образ; `no-new-privileges`. База и бэкенд наружу не опубликованы.
- **Права** проверяются на сервере в каждом роуте; интерфейс только прячет недоступные кнопки.
- **XSS:** React экранирует весь вывод, `dangerouslySetInnerHTML` не используется. Пароли — bcrypt,
  хеш никогда не попадает в ответы.
- **Секреты:** `.env` в `.gitignore`, в `.env.example` только заглушки, история коммитов проверена.

### Осознанные компромиссы

- **Токен в `localStorage`.** С заголовком `Authorization` не нужна защита от CSRF, а риск XSS
  закрыт CSP и экранированием. В мини-приложении токен заменяется проверкой `initData`.
- **Лимит попыток — в памяти процесса.** Для одного инстанса достаточно; при масштабировании
  счётчики переезжают в Redis, интерфейс `hit()` не меняется.
- **Регистрация сообщает, что почта занята.** Без этого человек не поймёт, почему не может
  зарегистрироваться; перебор почт через регистрацию ограничен тем же лимитом.
- **HSTS не включён** — локально нет HTTPS. В продакшене TLS и HSTS ставятся на внешнем прокси.

## Дизайн и доступность

Дизайн-система собрана через скилл `ui-ux-pro-max`: паттерн «каталог с поиском», плоский
стиль под касание, деловая палитра navy + синий CTA, шрифт Golos Text (сделан для интерфейсов
Госуслуг, кириллица нативная). Шрифт подключён локально, а не с Google Fonts: те из РФ грузятся
нестабильно, а свой шрифт к тому же не требует дыр в CSP.

- **Токены, а не цвета:** компоненты используют только семантические переменные. Тёмная тема —
  отдельная палитра, а не инверсия. Переключатель: системная / светлая / тёмная; в Telegram
  тема берётся из клиента.
- **Контраст проверен расчётом** для каждой пары текст/фон в обеих темах: весь текст — от 4.85:1
  (WCAG AA — 4.5:1), границы полей ввода — от 3.1:1 (WCAG 1.4.11).
- **Навигация адаптивная:** на телефоне — нижняя панель под большой палец, как в нативных
  приложениях; от 768px — верхнее меню. Учтены вырез и жестовая полоса (`safe-area-inset`).
- **Клавиатура и скринридеры:** ссылка «Перейти к содержимому», видимый фокус, фокус на
  заголовок при смене страницы, вкладки кабинета переключаются стрелками, диалоги на нативном
  `<dialog>` удерживают фокус и закрываются по Esc. Статусы дублируются иконкой и текстом —
  цвет никогда не единственный признак.
- **Формы:** подписи над полями, ошибки под полем и после ухода с поля, а не на каждую букву;
  после неудачной отправки фокус переходит на первое ошибочное поле, и оно не прячется под шапкой.
- **Тач-цели** от 44px — проверено скриптом на всех страницах. Анимации 120–200 мс и
  отключаются при `prefers-reduced-motion`.
- **Производительность:** скелетоны резервируют место (лента не прыгает при загрузке), страницы
  кроме ленты грузятся по требованию, устаревшие запросы отменяются при смене фильтра.

## Тесты

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Тесты идут на SQLite, чтобы запускаться без Docker. Три набора:
`test_applications.py` и `test_posts.py` — сценарии и права доступа,
`test_auth.py` — регистрация, вход, профиль,
`test_security.py` — по тесту на каждую находку аудита: поддельные и просроченные токены,
`alg=none`, перебор паролей, подмена IP, длинные пароли, шаблоны LIKE, лишние поля, заголовки,
отказ стартовать с небезопасной конфигурацией.

Аудит зависимостей:

```bash
cd backend && .venv/bin/pip-audit -r requirements.txt
cd frontend && npm audit
```

## Разработка без Docker

```bash
# бэкенд: нужен запущенный Postgres, адрес — в DATABASE_URL
cd backend && .venv/bin/alembic upgrade head && .venv/bin/uvicorn app.main:app --reload

# фронтенд: Vite проксирует /api на localhost:8000
cd frontend && npm install && npm run dev
```

## Использование ИИ

Весь код я писал в Claude Code. Случая, когда я построчно поймал модель на плохом
решении, у меня не было. Вместо этого я не принимал сгенерированный код как готовый:
прогнал тесты и аудит безопасности, и уже он показал реальные проблемы. Главная,
контакт автора прятался только в интерфейсе, а через API возвращался всем подряд;
ещё библиотека для токенов оказалась с известной уязвимостью подделки подписи.
После этого решение переписали, и на каждую находку есть тест.

Руками я проверял безопасность: поднимал приложение и ходил по сценарию, дёргал API
в обход интерфейса, чужие публикации и отклики, и гонял аудит зависимостей.
